四、手机端 vs 网页端 下载行为

场景手机端（iOS / Android）网页端（桌面 Chrome）
判定方式navigator.userAgent 含 Mobile / iPhone，或 innerWidth < 768同上判定为桌面
下载交互页面内全屏预览层 + 长按保存 / 「用浏览器打开」浏览器原生「另存为」对话框，指定文件名保存
图片来源同一套 html2canvas 截取 #planArea → PNG blob，所见即所得
取消处理用户在「另存为」点取消（AbortError）→ 直接中止，不渲染不下载

结论：两端下载的「图片内容」完全一致（同一渲染管线），仅交互外壳因平台能力不同而适配，符合「和网页端一样正常使用」的要求。

五、本轮方法论更正（重要透明说明）

⚠️ 第一版手机端扫描脚本误用了 isMobile:true 但未附带设备描述符，导致 Playwright 未真正切换 UA 与视口：浏览器 UA 仍是桌面 Chrome、innerWidth 实测 1008px。在该错误环境下，下载逻辑按「桌面」分支走、且未弹出预览层，一度误报恒享人生 / 宏御世家「下载无预览」。已修正为使用 Playwright 内置 devices['iPhone 13'] 设备描述符（UA=iPhone、视口 390×844、isMobile、触摸），重新实跑后全部通过——前述「2 处异常」为测试环境假阳性，非站点代码缺陷。

修正后复测结果：39 页布局 0 异常、12 项演算器专项 0 异常，本报告数据均来自该正确环境。
