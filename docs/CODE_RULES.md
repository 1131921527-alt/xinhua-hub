# 新华Hub 代码安全规则（CODE_RULES）

> **目的**：建立新华Hub AI 开发安全规范，防止 AI 在「优化 / 重构」时误改业务核心数据。
> **生效范围**：所有 AI（WorkBuddy / Codex / ChatGPT 生成代码）对 `xinhua-hub/` 的改动。
> **生成日期**：2026-07-30。本文只记录规范，**不修改任何代码**。

---

## 0. 总原则

- 任何 AI 改动前，**必须先读 `PROJECT_MAP.md` 与本文**，明确哪些动得、哪些动不得。
- 「看起来像重复代码 / 可优化」≠「可以改」；涉及数据源与公式的一律视为禁区。
- 本文与 `PROJECT_MAP.md` 的「禁止修改（数据源）」标注互为执行依据。

---

## 1. 禁止修改清单（🔴 红线）

以下四类**任何情况下禁止 AI 直接修改**。如需变更，须由人工在源头改，再走「生成脚本 → 校验」流程，不得让 AI 直接编辑产物。

| # | 禁改项 | 具体文件 / 位置 | 原因 |
|---|---|---|---|
| 1 | **Excel 导入数据** | `xlsx/*.xlsx`、`新华在售产品_中国银行版.xlsx` | 人工维护的真实源，改错则全站演算失真 |
| 2 | **收益计算公式** | 各 `calculator-*.html` 中的收益率 / 演算函数逻辑 | 公式即合规口径，AI 改即违规 |
| 3 | **产品利益数据** | `*_calcdata.js`、`data_*.json`、`hongyu_data.json`、HTML 内嵌演示数据 | 演示数值源头，手改即错 |
| 4 | **已验证页面模板** | 已通过 `tests/product-rule-check.js` 验收的 calculator 页面结构 / 样式 | 验收基线，无显式授权不得动 |

> 注：第 4 项特指**已通过验收**的页面。若确需调整样式，必须在流程中显式标注并重新跑测试（见 §2），不得静默改动。

---

## 2. 修改必须经过的流程（强制门禁）

任何**允许修改**的改动（新增产品、调整规则配置、修复非禁区 bug），必须依次走完四步，**前一步不通过不得进入下一步**：

```
修改前截图
   ↓  （记录改动前页面 / 数据状态，作为回归基准）
代码 diff
   ↓  （产出精确 diff，确认只动了允许区域，未触碰 §1 红线）
自动测试
   ↓  （重跑 node tests/product-rule-check.js，全绿 11/11 才放行）
修改后截图
   ↓  （记录改动后状态，与「修改前截图」对比确认无回归）
```

### 各步说明

| 步骤 | 产出 | 门禁条件 |
|---|---|---|
| ① 修改前截图 | `before-*.png`（桌面 + 手机） | 页面正常、数据正确，作为基准 |
| ② 代码 diff | `git diff` / 工具 diff | 确认无 §1 禁改项被触碰；仅动允许区域 |
| ③ 自动测试 | `tests/last-report.md`（须 11/11 通过） | 全部用例 ✅，无 console 报错、下载图与页面数据一致 |
| ④ 修改后截图 | `after-*.png`（桌面 + 手机） | 与 before 对比，展示 / 布局无回归 |

---

## 3. 违规处理与回退

- diff 发现触碰 §1 红线 → **立即回退**，不进入测试；记录原因并通知人工。
- 自动测试未全绿 → **禁止合并**，回到修改阶段定位。
- 所有改动须记入双写记忆（工作区 `.workbuddy/memory/` + `腾讯龙虾的成品/memory/`）。
