## 1. 现状诊断

### 1.1 全站页面盘点

当前 `data.json` 共 16 个分类、约 73 个条目。按性质归类：

## 2. 全站统一规范

### 2.1 🟢🟡🔴 三级真实性标识体系

**规范定义**（以③号页面现有体系为基准，全站统一）：

| 标识 | 含义 | 适用场景 | 视觉规范 |
|------|------|----------|----------|
| 🟢 | **资料明确** — 内容来自官方文件/条款/截图，已逐字核对 | 条款原文、监管文件、公司披露数据 | 绿色圆点 + "资料明确" 文字标签 |
| 🟡 | **AI整理** — 基于资料整理/归纳/翻译，非原文逐字 | 操作步骤整理、话术归纳、数据汇总 | 黄色圆点 + "AI整理" 文字标签 |
| 🔴 | **待核验** — 资料不完整/OCR未做/时效过期，需人工确认 | OCR占位区、过期信息、推测内容 | 红色圆点 + "待核验" 文字标签 |

**执行标准**：
- 每个内容段落/数据块/操作步骤都必须标注一个级别
- 页面底部设"来源映射表"，列出每个标识对应的原始资料
- 首页 data.json 的每个条目增加 `authenticity` 字段（full/partial/none），前端渲染时显示标识

**各页面改造量**：

| 页面 | 当前状态 | 改造工作量 |
|------|----------|-----------|
| ① 产品答疑手册 | ❌ 完全无标注 | **大** — 1032行需逐板块标注 |
| ② 红利实现率 | 🟡 有部分标注（🟡待验证+免责声明） | **中** — 补全为完整三级体系 |
| ③ 宏愿人生指引 | ✅ 已有完整三级标注 | **无** — 作为标杆模板 |
| ④ 电子保单指南 | ✅ 已有完整三级标注 | **无** — 已达标 |

### 2.2 来源标注规范

**统一格式**：每个页面底部必须包含"资料来源"区块，格式如下：

```
资料来源：
[1] 《文件名.pdf》—— 🟢 资料明确部分
[2] AI基于[1]整理归纳 —— 🟡 AI整理部分  
[3] OCR未完成/时效待核验 —— 🔴 待核验部分
免责声明：本页面仅供新华保险银保渠道内部参考，不作为客户投保依据。
```

**各页面改造**：

| 页面 | 当前来源标注 | 改造内容 |
|------|-------------|----------|
| ① | "一线实战经验整理"（无结构） | 区分"条款确认"与"经验归纳"，建立来源映射表 |
| ② | 有编辑整理说明+免责声明 | 补充来源编号列表 |
| ③ | 有逐项标注+适用范围提示 | 已达标，补充来源编号 |
| ④ | 有来源映射表 | 已达标 |

### 2.3 更新时间与版本号机制

**统一规范**：
- 每个HTML页面 `<head>` 中增加 `<meta name="version" content="v1.x">` 和 `<meta name="updated" content="2026-07-xx">`
- 页面底部右下角统一显示：`版本 v1.x · 更新于 2026-07-xx`
- data.json 每个条目增加 `version` 和 `updated` 字段，首页卡片可显示更新日期标签
- **数据型页面**（红利实现率、演算器）建立"更新日历"：每年7月同步官网最新披露

**各页面改造**：

| 页面 | 当前版本标注 | 改造内容 |
|------|-------------|----------|
| ① | "v1.0"（无日期） | 补充日期 + 升版本号 |
| ② | "2026年7月更新" | 统一为版本号+日期格式 |
| ③ | 无 | 新增版本号+日期 |
| ④ | "V1.1"（无日期） | 补充日期 |

## 3. 页面通用组件

### 3.1 复制客户话术按钮

**现状**：仅④号页面顶部有 `📋复制给客户` 按钮（clipboard API + execCommand兜底）。

**统一方案**：
- 封装为通用 JS 函数 `copyToClipboard(text, btnId)`，放入独立 `js/clipboard.js` 文件
- 所有页面的 `.script-box` / `.qa-answer` / 话术段落统一增加复制按钮
- 按钮样式统一：📋图标 + "复制"文字，复制后变为 "✓ 已复制"（2秒恢复）
- 移动端适配：按钮最小44px×44px触摸区域

**改造范围**：

| 页面 | 需要增加复制按钮的话术数量 | 优先级 |
|------|-------------------------|--------|
| ① 产品答疑手册 | ~30条script-box话术 | P1（量最大） |
| ② 红利实现率 | ~8条关键数据/话术 | P2 |
| ③ 宏愿人生指引 | ~5条操作提示话术 | P2 |
| ④ 电子保单指南 | 顶部已有，需扩展到其他段落 | P2 |

### 3.2 快速30秒入口

**现状**：仅④号页面有⚡"最快处理方式"蓝色高亮条。

**统一方案**：
- 在每个知识页面顶部（TOC之后、主体之前）设置"⚡ 30秒速查"区块
- 内容：最高频使用场景的3-5个关键操作/数据/话术，折叠/展开式
- 设计：蓝色渐变背景卡片，左侧⚡图标，右侧关键内容

**各页面30秒入口内容设计**：

| 页面 | 30秒入口内容 |
|------|-------------|
| ① 产品答疑 | 6大产品最核心的一句话卖点 + 最常见异议的标准回答（各1句） |
| ② 红利实现率 | "平均128% / 97款产品 / 最高233% / 连续5年超100%" 4个关键数字 |
| ③ 宏愿人生 | "已有双录订单→中行APP→搜索宏愿→填写→投保" 5步速览 |
| ④ 电子保单 | ✅ 已有（短信链接→客户点开→输入信息→获取保单） |

### 3.3 相关页面推荐

**现状**：4个页面完全独立，无任何交叉链接。

**统一方案**：
- 每个页面底部增加"📂 相关页面"区块，3-4个推荐链接
- 推荐逻辑：按客户业务流程的上下游关系
- 卡片式设计：图标 + 标题 + 一句话描述 + 跳转链接

**交叉链接矩阵**（业务流程顺序）：

```
了解产品 → 产品比较 → 测算 → 投保 → 双录 → 承保 → 保单查询 → 售后
   ①          ⚖️       🧮     ③      📹     📋       ④        ①
   ②                                                                  
```

**各页面推荐链接**：

| 当前页面 | 推荐链接 |
|----------|----------|
| ① 产品答疑 | → ②红利实现率（数据说服）/ → 演算器（测算）/ → ③投保指引（操作） |
| ② 红利实现率 | → ①产品答疑（异议处理）/ → 保险知识卡（利率政策）/ → 演算器（测算） |
| ③ 宏愿人生指引 | → ④电子保单指南（投保后查保单）/ → 双录准备（投保前）/ → 演算器（测算） |
| ④ 电子保单指南 | → ③宏愿人生指引（投保操作）/ → 电子回执回访（售后）/ → ①产品答疑（答疑） |

### 3.4 场景导航

**现状**：无跨页面场景导航，理财经理需自行判断"现在该看哪个页面"。

**统一方案**：
- 在首页（index.html）增加"场景导航"区块，按理财经理日常工作场景组织
- 每个场景卡片直接跳转到对应知识页面的特定锚点
- 移动端优先设计，横向滑动卡片

**场景导航设计**（6个高频场景）：

| 场景 | 触发时机 | 跳转目标 |
|------|----------|----------|
| 🔍 **客户问产品** | 客户在银行APP看到产品来问 | → ①产品答疑手册对应产品板块 |
| 📊 **客户质疑分红** | "分红不确定，能兑现吗" | → ②红利实现率专题页 |
| 🧮 **客户要测算** | "投入多少钱能拿多少" | → 演算器合集页 |
| 📝 **客户要投保** | "怎么操作买" | → ③宏愿人生投保指引 |
| 📋 **客户问保单** | "我的保单在哪里" | → ④电子保单指南 |
| 🔔 **客户问售后** | "买完之后呢" | → 电子回执回访 + 增值服务 |

## 4. 知识库结构升级

### 4.1 现状架构 vs 目标架构

**现状**：16个扁平分类，按"文件类型"组织（产品规则、合同模板、演算表……）

**问题**：理财经理找信息时想的是"客户现在到了哪一步"，而不是"我要找什么类型的文件"。

**目标**：按**客户生命周期**重新组织知识库，理财经理跟着客户流程走，自然找到对应工具。

### 4.2 客户生命周期8阶段架构

```
①了解产品 → ②产品比较 → ③测算方案 → ④投保操作 → ⑤双录流程 → ⑥承保确认 → ⑦保单查询 → ⑧售后服务
```

**各阶段对应内容映射**：

| 阶段 | 客户状态 | 理财经理动作 | 对应页面/工具 | 现有分类 |
|------|----------|-------------|-------------|----------|
| **① 了解产品** | 客户初次接触，想了解保险产品 | 介绍公司+产品概念 | 公司介绍页、产品答疑手册、保险知识卡、培训资料 | company-intro / sales-qa / knowledge-card / training |
| **② 产品比较** | 客户想对比不同产品 | 展示产品差异 | 中行产品清单、在售产品投保年龄表、产品对比图 | boc-calculators / product-compare / product-intro |
| **③ 测算方案** | 客户选定产品，想看收益 | 在线演算利益演示 | 演算器合集（中行6款+招行8款）、演算表Excel | boc-calculators / calculators / excel-tables |
| **④ 投保操作** | 客户决定购买，需指导操作 | 指导APP投保流程 | 宏愿人生投保指引、中行投保操作指引 | boc-calculators内嵌 / workflow |
| **⑤ 双录流程** | 银保渠道必须双录 | 双录资料核对+适当性评估 | 双录准备清单、适当性评估步骤 | boc-calculators内嵌 |
| **⑥ 承保确认** | 投保完成，等待承保 | 确认承保状态 | （暂无专门页面，可新建承保查询指引） | — |
| **⑦ 保单查询** | 客户问"保单在哪" | 30秒快速处理 | 电子保单获取指南、纸质保单申请 | workflow内嵌 |
| **⑧ 售后服务** | 保单生效后 | 回执回访+增值服务+保单复效 | 电子回执回访、保单复效、增值服务总览、居家养老 | workflow / vip-service |

## 6. 总结

### 核心判断

新华Hub当前处于"**内容丰富但结构散装**"的阶段——73个条目、16个分类，内容覆盖面广，但存在三个核心问题：

1. **合规层面**——①号页面（1032行、最大知识页面）无真实性标注，合规风险最高
2. **结构层面**——16个扁平分类不符合理财经理"跟着客户流程走"的使用习惯
3. **联动层面**——4个核心知识页面互相独立，3个未纳入首页导航

### V1.2 核心目标

| 目标 | 当前状态 | V1.2目标 |
|------|----------|----------|
| 真实性标注覆盖率 | 3/4页有（75%） | 4/4页有（100%） |
| 复制功能覆盖率 | 1/4页有（25%） | 4/4页有（100%） |
| 页面交叉链接 | 0条 | 12条（每页3条推荐） |
| 首页导航纳入率 | 1/4页（25%） | 4/4页（100%） |
| 统一页面模板 | 无 | 8区块标准模板 |
| 首页分类架构 | 16个扁平分类 | 8个生命周期阶段 |

### 一句话总结

> **V1.2 = 补合规标注 + 加通用组件 + 改生命周期架构**——先补短板（P0），再提效率（P1），最后改结构（P2），搜索和计算器等增强功能留到P3。
