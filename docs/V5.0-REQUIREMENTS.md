## 0. 一句话定位（最终目标 · 第10条）
**不做「保险资料网站」，做「理财经理每天工作的数字助手」。**

打开以后要能回答：
- 今天学什么？
- 客户来了怎么分析？
- 哪个产品适合？
- 方案怎么生成？
- 话术怎么说？

一切功能、内容、页面，都围绕这五个问题服务。

## 1. 产品级审查标准（第1–10条补充要求）

### 1.1 不堆功能，先解决场景（第1条）
- 不为了加模块而加模块。
- 每新增一个功能，必须能回答：**一个理财经理每天用它，解决什么具体问题？**
- 删除：低频、重复、没有实际价值的功能。

### 1.2 客户流程思维，不按文件分类（第2条）
不要只按网站栏目堆内容。按真实销售流程重设计：

| 场景 | 理财经理需要 |
|------|------|
| 场景一：客户第一次咨询 | 需求分析 / 产品筛选 / 推荐逻辑 / 话术 |
| 场景二：客户比较产品 | 产品对比 / 收益展示 / 优势差异 / 风险提示 |
| 场景三：客户犹豫 | 异议处理 / 常见问题 / 案例参考 |
| 场景四：成交后服务 | 保单服务 / 后续经营 / 转介绍逻辑 |

**网站围绕客户流程，而不是围绕文件分类。**

### 1.3 产品对比中心（第3条）
目前是单产品测算。必须增加**横向比较**：
- 例：「宏御和盈满鑫有什么区别？」
- 展示维度：缴费方式 / 期限 / 收益特点 / 适合客户 / 优势。
- 非常适合理财经理面对客户比价时使用。

### 1.4 客户案例库（第4条）
不要只有产品知识，优秀销售靠案例。案例结构：
- 客户背景（年龄 / 资金 / 家庭情况）
- 客户需求（养老？稳健增值？资产规划？）
- 推荐思路 / 沟通过程 / 最终结果
- 让新人可学习。

### 1.5 话术去「销售味」（第5条）
检查现有话术，避免：
- ❌ 保证赚钱
- ❌ 一定比银行高
- ❌ 零风险
改成专业财富规划表达：
- ✅ 安全性
- ✅ 确定性
- ✅ 长期规划
- ✅ 资产配置

### 1.6 全站搜索（第6条）
资料变多后必须有搜索：
- 搜「养老」→ 出现：产品 / 话术 / QA / 培训
- 搜「分红」→ 出现：所有相关内容

### 1.7 内容等级（第7条）
资料多后会乱，建立等级：
- ⭐ 推荐阅读
- ⭐⭐ 必学内容
- ⭐⭐⭐ 核心销售能力
新人打开知道先学什么；老员工知道查什么。

### 1.8 版本管理 / 更新日志（第8条）
每次升级必须记录：版本号（V5.0 / V5.1…）、日期、内容、原因。形成《新华 Hub 更新日志》（见 `docs/CHANGELOG.md`）。

### 1.9 两类客户沟通模型（第9条）
不要所有客户一个话术。分别建立：
- **老年客户沟通模型**：关注 安全 / 稳定 / 流动性 / 资金用途。
- **高净值客户沟通模型**：关注 家庭资产配置 / 长期规划 / 财富传承 / 风险隔离。

### 1.10 最终目标（第10条）
同 §0：理财经理每天工作的数字助手。

## 3. 防跑偏红线（沿用 + 新增）

沿用 `AI-development-rules.md`：
- 不动演算器公式 / 数据 / 算法 / 导出逻辑。
- 不删旧代码 / 不可恢复数据。
- 改样式只动 `theme.css` / `calc-common.css`；不整体重构。
- 优先级：手机 > 导出 > PC；网页 = PNG。
- 合规不能删销售真实场景；正式内容 / 销售话术分区。

新增（本总纲）：
- **每个新功能必须能回答「理财经理每天用它解决什么」**，否则不做（1.1）。
- **围绕客户流程设计，不围绕文件分类**（1.2）。
- **话术只用专业财富规划表达，禁「保证赚钱/一定比银行高/零风险」**（1.5）。
- **每次升级写更新日志**：版本号 + 日期 + 内容 + 原因（1.8）。
