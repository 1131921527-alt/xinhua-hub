任务1 · T010 自动验收体系升级执行方案

修改目的

当前验收体系存在覆盖盲区和断言缺失，无法为后续批量演算器升级提供安全网。需要补全覆盖面 + 加入 Console 错误断言，让每次改动都有自动回归保障。

用户价值

理财经理和泽少改完代码跑一遍脚本就知道：10 款演算器有没有横向滚动、有没有 JS 报错、导出图够不够宽、储备期和署名在不在。不用人工逐页点开检查。

# 在 pc = browser.new_page(...) 之后加：
console_errors = []
pc.on("console", lambda msg: console_errors.append(msg.text) if msg.type == "error" else None)
# 页面加载后检查：
if console_errors:
    problems.append(f"{key} pc: Console错误 {console_errors[:5]}")
手机端同理。建议封装为 collect_console_errors(page) 工具函数，避免重复。
改动 4：桌面端横向滚动检查
当前 check_hscroll() 只在手机端调用。在桌面端截图后也调一次： 
# 桌面端 shot_full 后追加：
ok_pc = check_hscroll(pc, key + "_pc")
hscroll_ok.append((key + "_pc", ok_pc))
改动 5：导出 PNG 高度检查
当前只检查 w < 1500。加入高度上限检查防止异常超大图： 
if h > 20000:
    problems.append(f"{key}: 导出高度 {h}px 异常，可能 html2canvas 重复渲染")

任务4 · T011 AI 知识助手 V1.0 架构方案

合规红线：AI 助手只召回已有资料，不生成新话术、不给投资建议、不回答超出已有资料范围的问题。所有输出可溯源到站内具体页面。

目标场景

理财经理在手机上输入客户需求/问题，系统返回：产品建议 + 相关资料 + 话术 + 培训内容 + 方案入口。

示例：用户输入"客户60岁，想养老，预算20万"

系统返回内容

返回模块内容数据来源

培训内容培训中心"养老规划"课程链接training.json
方案入口宏愿演算器一键跳转（带预填参数）calculator-hongyuan.html

架构设计

① 知识源清单（4 类）

类型来源格式更新频率
产品库data.json + data_*.jsonJSON随产品上线更新

② 召回/排序策略

  • 第一步：关键词匹配。用户输入分词后匹配知识源标签（养老/分红/传承/高客/异议）
  • 第二步：产品筛选。按用户输入的客户画像（年龄/预算/需求）匹配产品标签
  • 第三步：排序。产品按匹配度排序；话术按标签相关度排序；培训按内容等级⭐排序
  • 第四步：组装返回。每个模块取 Top 3，附跳转链接

V1.0 不用 LLM。纯规则匹配 + 标签索引，确保可控可溯源。V2.0 可考虑接入 LLM 做自然语言理解，但话术仍只召回不生成。
