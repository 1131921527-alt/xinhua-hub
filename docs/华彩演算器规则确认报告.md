# 华彩演算器规则确认报告

生成时间：2026-08-13

## 一、当前代码事实

### 1.1 页面输入控件

| 控件 | 范围/选项 | 是否影响金额计算结果 |
|---|---|---|
| 性别 | 男 / 女 | **否**（仅用于标题显示） |
| 投保年龄 | 0~72 周岁 | **否**（仅用于标题和表格年龄列显示） |
| 交费方式 | 趸交 / 3年交 / 5年交 / 10年交 | **部分影响**（影响缴费期列合并、储备期、总保费） |
| 年交保费 | 趸交最低5万，期交最低2万 | **是**（所有金额按 10 万基准线性缩放） |
| 分红方式 | 累积生息 / 交清增额 | **否**（当前代码未根据该选项切换数据或公式） |

### 1.2 底层数据源

文件：`calculator-huacai.html` 第 239 行内联 `HC_DATA`

唯一基准案例：

- 性别：女
- 年龄：35 岁
- 交费期间：3 年交
- 年交保费：100,000 元
- 基本保险金额：1,030 元
- 数据维度：45 个保单年度（yr 1~45，年龄 35~79 岁）

`HC_BASE = { age: 35, term: 3, prem: 100000 }`（第 311 行）

字段说明（每行 12 列）：

| 索引 | 字段 | 含义 |
|---|---|---|
| 0 | `yr` | 保单年度 |
| 1 | `age` | 被保险人年龄（35 岁基准） |
| 2 | `curr_prem` | 当年保费 |
| 3 | `cum_prem` | 累计保费 |
| 4 | `annuity_yr` | 当年年金/关爱金 |
| 5 | `annuity_cum` | 累计年金 |
| 6 | `maturity_ben` | 满期金 |
| 7 | `death_ben` | 身故保险金 |
| 8 | `cv` | 现金价值 |
| 9 | `cum_dividend` | 累计红利 |
| 10 | `survival_total_div` | 生存总利益 |
| 11 | `death_total_div` | 身故总利益 |

### 1.3 计算逻辑

`generate()` 函数核心片段（第 359~399 行）：

```javascript
const scale = premium / HC_BASE.prem;
const ageOffset = age - HC_BASE.age;
// ...
for (let idx = 0; idx < HC_DATA.length; idx++) {
  const row = HC_DATA[idx];
  const yr = row[0];
  const baseAge = row[1];
  const currentAge = baseAge + ageOffset;
  const currPrem = Math.round(row[2]*scale);
  const cumPrem = Math.round(row[3]*scale);
  const aAnn = row[4]>0 ? Math.round(row[4]*scale) : 0;
  // ... 所有金额字段均按 scale 缩放
}
```

核心问题：
- **性别不影响数据**：选男/女都用同一组女性 35 岁数据。
- **年龄不影响金额**：输入 40 岁或 60 岁，金额仍是 35 岁案例按保费缩放。
- `ageOffset` 仅用于 `currentAge` 显示，不改变任何金额字段。
- **交费期间只影响展示**：改变 term 会改变缴费期列合并、储备期计算、总保费，但 `HC_DATA` 中的现金流仍是 3 年交结构。
- 基本保额 `baseAmount = HC_DATA[4][4] * scale` 也仅按保费缩放。
- 分红方式选项未实际切换数据或公式。

## 二、条款依据

`clause-huacai.html` 明确：

1. **投保年龄**：0 周岁（出生满 28 日）至 72 周岁。
2. **保险期间**：至被保险人年满 105 周岁后的首个保单周年日。
3. **交费方式**：一次交清、3 年交（条款还可能有其他期间，页面提供 1/3/5/10 年交）。
4. **关爱金**：第 5 个保单周年日给付。
5. **满期金**：保险期间届满时按实际交纳保险费给付。

结论：**官方产品本身支持多年龄、多性别、多交费期间**。

## 三、问题定性

页面控件给出的自由度（年龄/性别/交费期/分红方式）**超出了底层数据支持范围**。

华彩比宏泰更隐蔽：`ageOffset` 让表格年龄列看起来随输入变化，但所有金额仍是 35 岁女/3 年交基准按保费缩放，容易让用户误以为结果是按所选年龄计算的。

## 四、方案对比

### 方案 A：如果短期内只能支持固定案例

**措施**：
1. 冻结性别为"女"。
2. 冻结投保年龄为 35 岁（或与官方理财计划书一致的默认案例）。
3. 冻结交费方式为 3 年交。
4. 保费可调整，按 10 万基准缩放。
5. 在页面明显位置提示："当前演示仅适用于官方默认案例，其他组合结果仅供参考"。

**优点**：
- 改动最小，不引入错误数据。

**缺点**：
- 与销售需求冲突：条款支持多年龄/性别/交费期，页面却无法演示。

### 方案 B：如果官方支持多参数

**措施**：
1. **补齐数据表**：需要按官方利益演示表，建立 `data_huacai.json`，覆盖：
   - 性别：男、女
   - 年龄：0~72 周岁，销售高频 30~65 岁
   - 交费期间：趸交、3年交、5年交、10年交
   - 数据维度：需覆盖到 105 周岁（当前 HC_DATA 只到 79 岁，但条款保险期间到 105 岁）
   - 保费：统一用每千元保费口径，页面按保费缩放
2. **重构 `generate()`**：从 `data_huacai.json` 按 `{gender}_{age}_{term}_{year}` 查表。
3. **处理分红方式**：累积生息和交清增额应使用不同数据或公式。
4. **保险期间到 105 岁**：补齐 80~105 岁数据，或确认是否只演示到 79 岁。

**数据量估算**：
- 性别 2 × 年龄约 50 × 交费期 4 × 保单年度约 70 = 约 28,000 个数据点
- 每个数据点 12 个字段 ≈ 336,000 个数值

**优点**：
- 符合条款支持范围，满足销售需求。

**缺点**：
- 需要大量官方标准数据。
- 需要重构数据加载和计算逻辑。

## 五、建议

鉴于条款明确支持多年龄/性别/交费期，**推荐方案 B**，但分阶段实施：

1. **第一阶段**：获取官方标准数据，优先覆盖销售高频组合：
   - 女 35/40/45/50 岁，3年交/5年交
   - 男 40/45/50 岁，3年交/5年交/趸交
2. **第二阶段**：将 `HC_DATA` 迁移为 `data_huacai.json`，键格式：`{gender}_{age}_{term}_{year}`。
3. **第三阶段**：修改 `generate()` 支持查表，保费缩放。
4. **第四阶段**：回归验证 + 提交 GitHub。

在补齐数据前，**建议限制页面输入**，避免用户选择不支持的组合。

## 六、是否影响其他演算器

本次为分析报告，未修改代码，不影响其他演算器。
