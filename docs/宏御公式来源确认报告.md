## 一、当前代码事实

### 1.1 0.01225 在代码中的使用

文件：`calculator-hongyu.html` 第 375~380 行

```javascript
// K = 年度交清增额基本保险金额（Excel K列）
// 第1年: K = ROUND(M * 份数 * 10000 / O, 0)
// 第2年+: K = ROUND((M * 份数 * 10000 + L_prev * O_prev * 0.01225) / O, 0)
let k;
if (yr === 1) {
  k = Math.round(M * scale * 10000 / O);
} else {
  k = Math.round((M * scale * 10000 + cumK * prevO * 0.01225) / O);
}
```

变量说明：

| 变量 | 含义 |
|---|---|
| `M` | 当年红利金额（元/千元保费），来自 `CALC_DATA` 第 13 列 ÷ 100 |
| `scale` | `premium / 1000`，即份数 |
| `O` | 当年交清增额净保险费（per 1000 保额），来自 `CALC_DATA` 第 15 列 |
| `cumK` | 上一年累计交清增额基本保险金额（L_prev） |
| `prevO` | 上一年交清增额净保险费（O_prev） |
| `0.01225` | 固定调整系数 |

### 1.2 代码注释

代码注释明确说明："使用与 Excel 完全一致的递归公式计算 K/L/N"。

### 2.3 业务含义推断

从公式结构看：

```
K = (当年红利可购买的交清增额保费 + 上一年累计交清增额保额 × 上一年净保费 × 0.01225) / 当年净保费
```

`L_prev * O_prev` 表示上一年累计交清增额保额按上一年净保费折算的保费总额。乘以 0.01225（即 1.225%）后作为附加项加入分子，再除以当年净保费，得到当年新增交清增额保额。

结合产品条款 `clause-hongyu.html` 第九条：

> "购买交清增额保险：根据被保险人性别、投保年龄及保单年度，以红利作为一次交清保险费购买交清增额保险，增加本合同的累积交清增额基本保险金额。"

推断 0.01225 是官方精算模型中交清增额保险的一个**预定调整系数**（可能与费用率、利息率或保额转换系数相关），但条款正文未明确写出该数值。
