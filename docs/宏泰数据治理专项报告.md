# 宏泰世家（分红型）数据治理专项报告

生成时间：2026-08-13
数据来源：`新华人寿 宏泰世家（分红型）.xlsx` → Sheet「宏泰世家终身寿险（分红型）相关利益演示数据」
分析原则：仅读取官方资料，不经验补数据、不生成模拟数据。

---

## 一、官方 Excel 结构

文件共 4 个 Sheet，与数据治理相关的核心是全表：

| Sheet | 行数 | 说明 |
|---|---|---|
| 宏泰世家（分红型）利益演示 | 198 | 产品介绍/投保示例页（含女49/3年交/50万示例） |
| 宏泰世家终身寿险未发生减保利益演示 | 121 | 单一示例（女49/3年交/50万）数值演示 |
| 宏泰世家终身寿险发生减保后利益演示 | 119 | 减保后示例 |
| **宏泰世家终身寿险（分红型）相关利益演示数据** | **37,983** | **全量利益演示数据表（关键）** |

全量表关键事实：
- 行数：37,979 条有效数据（去除表头）
- 主键格式：`{gender}_{age}_{term}_{year}`，例如 `1_49_3_1` = 女 / 49岁 / 3年交 / 第1年
- 口径：**每千元保费**（当年保险费列恒为 1000，累计保险费按 1000 递增）
- 维度覆盖：性别 0(男)/1(女) × 年龄 0~67 岁 × 交费期间 1/3/5/10 年 × 保单年度

## 三、data_hongtai.json 设计方案

**键格式**：`{gender}_{age}_{term}_{year}`（与官方主键一致，也与盈满鑫/宏愿等现有 JSON 风格统一）

**数值口径**：每千元保费。页面保费缩放方式改为 `scale = premium / 1000`（与宏愿/宏安等一致），替换现有 `scale = premium / 500000` 的单基准写法。

**字段集**（每条记录）：
```json
{
  "gender": 1, "age": 49, "term": 3, "year": 1,
  "prem": 1000, "cum_prem": 1000,
  "sa_death": null, "exempt_accident": 3997.5, "cv": 306,
  "guar_annual_div": 0, "guar_cum_div": null,
  "div_annual": 9.07, "div_cum": null,
  "paidup_net": 9985, "paidup_cv": 5311
}
```

**覆盖率**（草案实测）：
- 性别：男(0) / 女(1) 全覆盖
- 年龄：0 ~ 67 岁，共 68 个年龄点
- 交费期间：1 / 3 / 5 / 10 年
- 组合总数：521 个 (gender,age,term) 组合，37,979 条年度记录

## 四、是否可以替代现有 HONGTAI_DATA

**结论：可以，且应当替代。** 证据充分：

1. 官方全量表明确覆盖**多性别、多年龄、多交费期间**，证明产品本身支持这些维度——现有单案例硬编码（仅女49/3年交/50万）属于用错误近似覆盖全部输入，已确认会产生错误金额。
2. 官方数据主键结构与现有项目其他演算器（盈满鑫、宏愿）完全一致，迁移后数据管理模式统一。
3. 仅剩的一个工程问题：第 8/12/14 列部分单元格为公式占位，需在代码迁移前确定补齐策略（按条款公式算，或仅展示数值列）。

**迁移前置条件（待确认）**：
- 占位字段（sa_death / guar_cum_div / div_cum 等）的兜底计算规则；
- 年化单利 rate_raw 是否仍由页面按 (survival-prem)/prem/yr 计算，还是需官方提供；
- 基本保额 sumAssured 改用官方第 4 列（每千元保费对应保额）还是保留公式。
