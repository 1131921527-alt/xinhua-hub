# 宏泰演算器规则确认报告

生成时间：2026-08-13

## 一、当前代码事实

### 1.1 页面输入控件

| 控件 | 范围/选项 | 是否影响计算结果 |
|---|---|---|
| 性别 | 男 / 女 | **否**（仅用于标题显示） |
| 投保年龄 | 0~73 周岁 | **否**（仅用于标题和表格年龄列显示） |
| 交费方式 | 一次交清 / 3年交 / 5年交 / 10年交 | **部分影响**（影响缴费期列合并、储备期、基本保额缩放） |
| 年交保费 | 1000 元起，千元整数倍 | **是**（所有金额按 50 万基准线性缩放） |

### 1.2 底层数据源

文件：`calculator-hongtai.html` 第 207 行内联 `HONGTAI_DATA`

唯一基准案例：

- 性别：女
- 年龄：49 岁
- 交费期间：3 年交
- 年交保费：500,000 元
- 数据维度：22 个保单年度（yr 1~22）

字段说明：

| 字段 | 含义 |
|---|---|
| `yr` | 保单年度 |
| `age` | 被保险人年龄（49 岁基准） |
| `prem` | 当年保费 |
| `exempt` | 豁免金额 |
| `guar_amt` | 保证身故/全残保险金 |
| `exp_amt` | 预期身故/全残保险金 |
| `div_pv` | 红利现金价值 |
| `cv_guar` | 保证现金价值 |
| `cv_total` | 总现金价值 |
| `rate_raw` | 年化单利 |

### 1.3 计算逻辑

`getRows()` 函数（第 233~249 行）：

```javascript
const premium = parseInt(document.getElementById('premium').value) || 500000;
const base = 500000;
const scale = premium / base;
return HONGTAI_DATA.map(r => ({
  yr: r.yr, age: r.age,
  prem: Math.round((r.prem || 0) * scale),
  exempt: Math.round((r.exempt || 0) * scale),
  guar_amt: Math.round((r.guar_amt || 0) * scale),
  exp_amt: Math.round((r.exp_amt || 0) * scale),
  div_pv: Math.round((r.div_pv || 0) * scale),
  cv_guar: Math.round((r.cv_guar || 0) * scale),
  cv_total: Math.round((r.cv_total || 0) * scale),
  rate_raw: r.rate_raw
}));
```

核心问题：
- **性别不影响数据**：选男/女都用同一组女性 49 岁数据。
- **年龄不影响数据**：输入 30 岁或 60 岁，金额仍是 49 岁案例。
- **交费期间只影响展示**：改变 term 会改变缴费期列合并、储备期计算、基本保额，但 `HONGTAI_DATA` 中的保费现金流仍是 3 年交结构。
- 基本保额 `sumAssured = 1332500 * (premium / 500000)` 也仅按保费缩放，未考虑年龄/性别变化。

## 二、条款依据

`clause-hongtai.html` 明确：

1. **投保年龄**：0 周岁（出生满 30 日）至 67 周岁，男性最高 64 周岁、女性最高 67 周岁。
2. **保险期间**：终身。
3. **交费方式和交费期间**：由投保人与保险公司约定，条款未限定具体选项。
4. **交清增额**：明确根据被保险人性别、投保年龄及保单年度计算。

结论：**官方产品本身支持多年龄、多性别、多交费期间**。

## 三、问题定性

页面控件给出的自由度（年龄/性别/交费期）**超出了底层数据支持范围**。

当前实现属于"用单一基准案例近似所有组合"，存在系统性数据偏差风险。

## 四、方案对比

### 方案 A：如果短期内只能支持固定案例

**措施**：
1. 冻结性别为"女"。
2. 冻结投保年龄为 49 岁（或与官方理财计划书一致的默认案例）。
3. 冻结交费方式为 3 年交。
4. 保费可调整，按 50 万基准缩放。
5. 在页面明显位置提示："当前演示仅适用于官方默认案例，其他组合结果仅供参考"。

**优点**：
- 改动最小，不引入错误数据。
- 避免用户误以为可以自由选择真实参数。

**缺点**：
- 与销售需求冲突：条款支持多年龄/性别/交费期，页面却无法演示。

### 方案 B：如果官方支持多参数

**措施**：
1. **补齐数据表**：需要按官方利益演示表，建立 `data_hongtai.json`，覆盖：
   - 性别：男、女
   - 年龄：0~64（男）、0~67（女），或按销售高频年龄段 30~65 岁
   - 交费期间：1/3/5/10 年（以页面选项为准）
   - 保费：统一用每千元保费口径，页面按保费缩放
2. **重构 `getRows()`**：从 `data_hongtai.json` 按 `{gender}_{age}_{term}_{year}` 查表，而不是用单一基准。
3. **基本保额计算**：如果仍用 `1332500 * (premium/500000)`，需确认不同年龄/交费期的保额是否还是这个比例；否则应来自官方数据表。
4. **储备期和缴费期合并逻辑**：已有 `getProductRule('hongtai')`，可保留。

**数据量估算**：
- 性别 2 × 年龄约 50 × 交费期 4 × 保单年度约 70 = 约 28,000 个数据点
- 每个数据点 10 个字段 ≈ 280,000 个数值
- 建议按 JSON 查表 + 页面缩放保费的方式管理

**优点**：
- 符合条款支持范围，满足销售需求。
- 数据口径统一后，与其他演算器（宏安/宏愿）模式一致。

**缺点**：
- 需要大量官方标准数据。
- 需要重构 `getRows()` 和数据加载方式。

## 五、建议

鉴于条款明确支持多年龄/性别/交费期，**推荐方案 B**，但分阶段实施：

1. **第一阶段**：先获取官方标准数据。至少覆盖销售高频组合：
   - 女 40/45/50/55/60 岁，3年交
   - 男 40/45/50/55/60 岁，3年交/5年交
2. **第二阶段**：将 `HONGTAI_DATA` 迁移为 `data_hongtai.json`，键格式：`{gender}_{age}_{term}_{year}`。
3. **第三阶段**：修改 `getRows()` 支持查表，保费缩放。
4. **第四阶段**：回归验证 + 提交 GitHub。

在补齐数据前，**不建议继续让用户自由选择年龄/性别/交费期**，否则输出结果不可靠。

## 六、是否影响其他演算器

本次为分析报告，未修改代码，不影响其他演算器。
