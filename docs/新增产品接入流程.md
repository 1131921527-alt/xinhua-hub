# 新增产品接入流程（V1.0）

> 目标：以后新增一款产品，只需 **5 步**，且**不改动已有 10 个演算器文件**。
> 适用：新华Hub 资料库 V1.0 架构（已抽离 `product-rules.js` 统一规则层）。
> 红线同 V1.0：❌ 不改 Excel 原始数据 ❌ 不改收益公式 ❌ 不重设计储备期 ❌ 不大规模重构。

---

## 一、为什么现在能「只加不改」

此前每加一款产品要改 10 个文件，是因为「储备期 / 收益率展示」逻辑写死在各 HTML 里。
V1.0 已把 8 款产品的展示规则抽成配置层：

- `product-rules.js`：`window.PRODUCT_RULES`，新增产品**只加 1 条**即可。
- 演算器 HTML 通过 `resolveReserveYears(rule, payTerm)` / `evalReserveRule(rule, row)` 统一读取，**不再各写各的**。
- 福盛世家、恒享保持本地逻辑（非分红、无储备期体系），不强制进配置层。

---

## 二、5 步流程

### 第 1 步：准备产品数据（新增文件，不改旧文件）
- 来源：官方 Excel（`xlsx/` 真源，**禁止修改**）或从中导出的 `data_xxx.json`。
- 产出：新建 `calculator-xxx.html`（复制最近的同类型演算器做模板，如 `calculator-hongyu.html`），
  把本产品利益数据填进去。**不改动其他 9 个已有演算器。**

### 第 2 步：配置规则层（只改 1 处）
在 `product-rules.js` 的 `PRODUCT_RULES` 加一条：
```js
xxx: { reserveType: "fixed", reserveYears: 5, showRate: true }
// reserveType 可选：
//   "fixed"   固定年限（用 reserveYears）
//   "payterm" 储备期 = 交费期（盈满鑫规则）
//   "dynamic" 动态判定（用 rule，如 "rate<=0"，宏禧来）
// showRate: 储备期后是否展示收益率（华彩/宏坤 = false → 显示 "-"）
```

### 第 3 步：加产品介绍（新增文件）
- 在 `files/产品介绍/` 放产品介绍页 / 知识卡片。
- 如需在首页「产品介绍」分类出现，在 `data.json` 的 `product-intro` 分类加一条 item。

### 第 4 步：加计划书图片（新增文件 / 生成）
- 计划书由首页「智能计划书」或演算器「下载图片」生成 PNG。
- 如需静态计划书图，放 `files/` 并通过 `data.json` 登记。

### 第 5 步：跑测试（验证）
```bash
node tests/product-rule-check.js   # 10 款生成 / 下载 / 储备期校验
node tests/health-check.js         # 输出 V1.0-health-check.json
```

---

## 三、在首页登记（让理财经理找得到）

编辑 `data.json`：
- `calculators` 分类加 item → 在线测算入口
- `product-intro` 分类加 item → 产品介绍入口
- 如需进「中行在线演算合集」，改 `boc-calculators.html` 的列表

---

## 四、红线（接入时同样遵守）
- ❌ 不修改 `xlsx/` 任何 Excel 原始数据
- ❌ 不修改任何收益率 / 利益计算公式
- ❌ 不重新设计储备期规则（只配 `product-rules.js`）
- ❌ 不大规模重构

---

## 五、验证清单
- [ ] `product-rules.js` 已加条目，key 与 calculator 文件名一致
- [ ] 演算器页面可生成、可下载 PNG
- [ ] 储备期 / 收益率显示符合 `PRODUCT_RULES`
- [ ] `data.json` 首页卡片出现且链接正确
- [ ] `node tests/product-rule-check.js` 全绿
- [ ] 移动端（微信）字体 / 按钮 / 表格正常

---

## 六、反模式（以前要改 10 个文件，现在不用）

| 旧做法（禁止） | 新做法 |
|---|---|
| 在 10 个 HTML 各写一遍储备期判断 | 只写 `product-rules.js` 1 条 |
| 每个产品手写下载逻辑 | 共享 `html2canvas` + `downloadImage()` |
| 首页卡片硬编码在多处 JS 数组 | 集中在 `data.json` 一处维护 |

> 说明：目前「演算器本体 HTML」仍需基于模板新建（产品利益数据天然各异），
> 但**不再需要回改任何已有文件**——这是相比旧流程最关键的简化。
