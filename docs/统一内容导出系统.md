# 新华Hub统一内容导出系统

更新：2026-10-26。以不改变业务数据、原有计算器和已存在下载功能为前提，先接入已验收的正式内容页。不是给所有历史HTML、内部培训原件、审核稿、客户截图和计算器输入区盲目添加导出按钮。

## 架构与接入

正式页面/已确认模块的当前DOM → 公共组件快照 → 独立iframe排版 → 语义拆分/逐行表格卡片 → 安全画布 → PNG、PDF或视觉PPTX。

- `assets/js/content-export.js`：页面注册表、准备资源、筛查、独立排版、分页、渲染、ZIP、真实下载/预览及分享。只克隆页面实际内容，不另写利益数字。
- `assets/css/content-export.css`：隔离的菜单样式，不覆盖正文与计算器。
- 页面只增加公共CSS与defer脚本。注册表指定正式正文根节点、加载就绪条件、允许格式和可选的主题范围。
- 新页面接入须先确认来源/隐私及根节点，再添加一条注册记录与两处引用，运行本文件所列验收。不得自动把审核中的本地原型变成正式页面。
- 原有主题图片、模块拼装器及理财计划书导出入口保持不变。本轮不改计算器公式、条款、产品数据或GitHub Pages构建方式。

## 清晰度与安全

- PNG设计宽750px、默认1.5倍渲染，正文26px，按内容自动拆成连续编号图片；过长页面提供真正ZIP打包。每次画布限制约280万像素，渲染后立即释放画布，不生成无限高Canvas。预览按需加载，避免同时解码几十张大图。
- 手机PDF为108×192mm竖屏，正文30px，4mm边距；A4为210×297mm，独立字号/分页，不把桌面整页缩进纸张。PDF当前直接下载的是高清图像型，不支持选择正文文本；菜单另提供浏览器打印版，中文文本可选择和搜索。
- 视觉PPTX为真实OOXML文件，16:9，每页独立1280×720设计画布，按主题和内容块分页，不把整张长图压入一页。图片保持16:9，不拉伸。幻灯片备注保留对应文本与来源URL，但正文不是逐元素可编辑的文字、图表。
- 导出前等待字体、图片与样式；Canvas图表复制当前像素，保留SVG。图片失败或跨域不许可时明确报错，不留白假成功。
- 复杂表格按原始行、层级表头、rowspan/colspan展开为卡片；简单表格分页重复表头。分页前后严格核对正文文字，仅忽略明确标记的重复表头。放不下的单个图表不会被裁切、拉伸或强行缩成小字。
- 完成文件生成不等于浏览器已保存。菜单提供真实文件、大小、查看、下载和可用时的系统分享；微信提示查看后长按保存或在浏览器中打开。没有调用成功不宣称已经保存到相册。
- 拒绝私密标记、疑似身份证/手机号码及未确认状态的根节点；剔除needs_review/missing_source/calculation_pending模块。注册表是人工审查的公开内容白名单，不是通用隐私识别器；图片中的人脸、签名、二维码等仍须人工审查。不能以自动检测替代脱敏。

## 测试与当前限制

真实执行：Windows Chrome 390/430/1440，全部14页PNG；三个试点的两类PDF及PPTX；WebKit+iPhone参数模拟、Android Chrome参数模拟、微信UA模拟；SVG、Canvas、复杂表格、可选文字打印版、隐私拒绝及缺图失败。

以下不标记通过：真实iPhone Safari、真实Android、真实微信系统分享/相册保存、PowerPoint/WPS应用打开。PPTX已通过ZIP CRC、OOXML、16:9及每页图像结构检查，菜单明确标注视觉型试用，应用级验收待补。

WorkBuddy独立QA入口已实际尝试，返回Authentication required，未执行独立批量验收；不能把Codex自己的结果记成WorkBuddy通过。完成WorkBuddy登录后，按只读QA任务书补跑，不需要提供密码或Token给助手。

```text
node tests/content-export.spec.cjs <项目外验收目录>
```
